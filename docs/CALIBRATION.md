# 校正と座標系

## XMLの形式

各カメラで撮影時の解像度に合わせたOpenCV XMLを用意します。

```xml
<?xml version="1.0"?>
<opencv_storage>
  <image_width>1920</image_width>
  <image_height>1080</image_height>
  <camera_matrix type_id="opencv-matrix">
    <rows>3</rows><cols>3</cols><dt>d</dt>
    <data>fx 0 cx 0 fy cy 0 0 1</data>
  </camera_matrix>
  <distortion_coefficients type_id="opencv-matrix">
    <rows>1</rows><cols>5</cols><dt>d</dt>
    <data>k1 k2 p1 p2 k3</data>
  </distortion_coefficients>
</opencv_storage>
```

`fx`などは説明用の名前です。実ファイルでは数値に置換してください。内部行列は3×3のdouble、歪み係数はOpenCVの対応形式です。解像度を変更したら再校正するか、対応する内部パラメータを用意してください。

入力画像を `GetOptimalNewCameraMatrix` / `InitUndistortRectifyMap` / `Remap` で歪み補正し、補正後の内部行列を距離計算にも使います。元コードは画像だけ補正し、計算では元の固定値を使っていました。

## 距離の近似

各画像の虹彩中心（468・473番）を `(x-cx)/fx`, `(y-cy)/fy` で正規化します。2画像の正規化座標の差の大きさを `d` とし、深さを `baselineMeters/d`、横・縦位置を平均正規化座標×深さで求めます。画像の下方向をUnityの上方向へ反転します。

この式は元試作と同じ近似モデルです。歪み補正はステレオ平行化とは異なります。垂直視差やカメラの回転があると深さが偏ります。左右カメラの外部パラメータが元プロジェクトに存在しなかったため、正確な三角測量としては扱いません。将来はステレオ校正・対応点検証・平行化・三角測量へ置換できます。

検出対象は各画像の1人です。同一人物かどうかのID照合はありません。2台の画角に1人だけが入る配置を前提にします。フレームの取得時刻は同じStopwatchを使用し、鮮度と取得時刻の差で結果を棄却します。この時刻はカメラの露光時刻ではありません。

## 投影

画面TransformのローカルXYが物理画面、+Zが仮想空間の奥です。観察者はZ<0。追跡点の正の深さを負のZへ変換して左右カメラを置きます。元試作の物理カメラ焦点距離とlensShiftを直接変更する処理は、画面四隅から求める非対称投影に置き換えました。

USBカメラの基準位置と画面中心にはずれがあるため、`Viewer Offset Meters` で補正します。`Invert X/Y` は設置方向に合わせて設定します。厳密な画面との座標変換を校正する機能はまだありません。画面の前面に視点があること、既知の位置へ移動すると期待した方向へ映像が変わることを確認してください。

## 実機確認

1. カメラごとの解像度と校正XMLを一致させる。
2. 既知の距離を複数測定して深さ・左右位置・左右目の間隔を比較する。
3. 顔を隠した際に位置が発散しないこと、復帰時に追従することを確認する。
4. Play停止・再開、カメラ切断、カメラ番号誤りを確認する。
5. カメラと画面の座標ずれ、追従の遅延を確認する。

キャプチャスレッドの停止待ちは1秒に制限しています。ドライバのReadが戻らない場合、Unityを無期限に止めず、ドライバが戻った時点でそのワーカーがネイティブハンドルを解放します。まだ停止していないカメラを即座に再開すると競合する可能性があります。
